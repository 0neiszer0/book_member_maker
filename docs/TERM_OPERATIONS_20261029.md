# 학기 임원·업무·출석 개선

상태: 로컬 구현·검증 완료, 운영 반영 승인 전. 운영 기준 앱은 001671a4199bf36a00255801aaefbdd152c55244, Worker는 6678c791-2994-4ed5-ac37-416c87dd2b1b. 2026-10-29 SSH 재조회 시 앱·알림 타이머·Tunnel 정상. Render와 GitHub main은 변경하지 않는다.

## 사용자와 확정한 동작

- 학기 참여자 명단을 확정하고 회차에서는 예정 참석자를 기본 선택한다. 불참자를 해제한 뒤 실제 출석을 명시적으로 확정한다. 과거 회차는 저장된 명단을 먼저 보여주고 선택한 회차를 일괄 확정한다. 저장 명단이 없는 과거 회차는 현재 회원을 자동 소급하지 않고 개별 확인을 요청한다.
- 전역 기본 직책은 회장·부회장·총무·기획부장·학술지원부장·홍보부장 및 세 부서 부원이다. 기본 회원 관리는 회장/부회장/총무, 출석은 세 부장이 공동 담당한다. 전체 관리자가 학기마다 실제 회원을 배치하고 개별 담당 업무를 선택한다.
- 직책 구조·기본 권한은 전체 설정에서 바꾼다. 배치·담당 업무는 학기 안에서 관리한다. 직책 기본값을 쓰는 배치는 전체 수정이 반영되고, 직접 선택한 업무는 유지된다. 부원은 지정된 업무만 완료할 수 있고 담당자 배치 권한은 전체 관리자에게만 있다.
- 미처리 업무는 해당 화면으로 바로 연결한다. 공동 담당 업무는 한 명이 처리하면 모두의 알림/목록에서 해결된다. 새 신청·출석 업무는 기존 5분 타이머에서 생성하며 미처리 업무 요약은 매일 13:00 KST 이후 첫 실행에서 한 번 만든다. 반복 업무는 한 번/매일/매주/매월과 시간 선택, 기본 13시. 별도 자동화 앱 작업을 만들지 않는다.
- 알림 개별/모두 읽음 및 내 목록 삭제. 삭제는 soft delete이며 업무 완료와 구분한다. 읽음/삭제해도 남은 업무의 다음 날 요약은 온다. 권한 회수 후 기존 알림의 표시·푸시·작업 접근도 다시 검사한다.
- 과거 학기는 `25-1학기`, `25-여름학기`, `25-2학기`, `25-겨울학기`로 표기한다. 3–6월/7–8월/9–12월/다음 해 1–2월. 현재 존재하는 학기의 기간과 저장된 기록은 수정하지 않는다. 조사 시 과거 과목 숨김 설정은 0건이며, 새 과목도 기존 숨김 기능을 사용한다.
- 홈페이지·로그인 공유 제목은 `책반우|경북대학교 중앙독서동아리`, 기본 설명은 `책 먹는 호반우 홈페이지`. 기존 KNU 책반우 이미지를 유지한다. 개별 글의 제목은 유지한다.

## 검증과 한계

- PGlite 격리 PostgreSQL: migration 실행, 역할별 범위, 배치 revision 충돌, 출석 일괄 저장/기록 갱신/불참자 차단/타임스탬프 비교/학기 명단 revision 충돌, 가입 승인 권한, 공동 업무 완료·알림 정리, RLS 및 RPC 권한 검증 통과.
- 합성 데이터 localhost 화면: 역할 배치와 부원 업무 override 저장, 매주 목요일 13시 업무 등록, 출석 선택→미리보기→확정→출석표 O 표시, 알림 모두 읽음·삭제 검증. 새 흐름에 native confirm 팝업이 없어 사용자 조작 없이 진행했다. 390px에서 화면 넘침 없음.
- 실제 회원의 출석을 확정하거나 임원을 임의 배치하지 않았다. 기존 ‘확정이 안 된다’는 문제의 운영 오류는 재현되지 않았으므로 특정 원인으로 단정하지 않는다. 이번 변경은 확정 경로를 명시하고 권한·동시 수정·오류 안내를 개선한다.
- 실제 브라우저 푸시 수신은 배포 후 사용자 기기에서 확인해야 한다. 테스트 중 실제 푸시는 발송하지 않았다.
- 새 임원 배치를 저장하기 전에는 기존 전역 운영진 권한을 유지한다. 담당자가 없으면 활성 전체 관리자가 알림을 받는다. 배포 후 실제 임원 이름은 관리 화면에서 지정해야 한다.

## 데이터와 배포 순서

Migration: `supabase/migrations/20261029014149_term_operations_tasks.sql`.
신규 테이블 5개(operation_roles, term_officers, operation_rules, operation_tasks, operation_audit), 학기/알림 메타데이터 열, 서버 전용 함수 및 기존 회원명단/명단반영/가입처리 RPC 보완. 기본 직책 9개 외 실제 회원 명단·출석·계정 데이터는 SQL로 변경하지 않는다. 일괄 출석은 하나의 트랜잭션이고 학기·회차 버전이 다르면 전체 저장을 거절한다. 명단/출석/가입/공동 업무 처리와 관련 알림 정리는 DB 안에서 함께 실행한다.

1. 작업 루트 `outputs/operations-improvements-state.json`의 소스·준비물·승인 상태 확인. 최신 운영 커밋이 다르면 중단하고 다른 세션 변경을 먼저 비교한다.
2. 사용자에게 SQL·앱·Worker CDN 및 기존 알림 타이머를 통한 운영 알림 적용 승인을 받는다. DB 전체 자동 복구 백업은 아직 없음을 알린다. 로컬 DB 이전/서버 패키지 설치는 별도다.
3. 승인 후 기존 함수 정의를 복구 참고용으로 보관하고 migration을 트랜잭션 적용한다. 실패하면 전체 롤백된다. 적용 후 권한·열·함수만 읽기 확인한다.
4. 기존 정적 버전을 보존하는 Worker CDN을 먼저 배포한다. 앱 소스/manifest를 정확한 승인 커밋으로 설치하고 앱과 기존 알림 실행을 안전하게 교체한다. 새 의존성·새 비밀키·새 타이머는 없다.
5. 앱/DB health, 공개 GET, 로그인 시작, 정적 캐시·바이트, 공유 태그, 앱/위키/Tunnel/알림 타이머를 검증한다. 실제 회원 데이터 변경 테스트는 하지 않는다. 카카오 미리보기 갱신은 홈페이지 URL만 대상으로 수행한다.
6. 회귀 시 알림 타이머를 중단하고 직전 앱/manifest/Worker로 복구한다. 추가 스키마·업무 기록은 삭제하지 않는다. 업무 배치나 데이터가 실제로 바뀐 뒤에는 그 변경을 보존하면서 권한 호환성을 점검한다. SQL down migration이나 전체 DB 덮어쓰기를 자동 실행하지 않는다.
