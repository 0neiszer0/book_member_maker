# UI·사용성 개선 구현 계획 및 검증 범위

기준 커밋: `22bb06b9484c5ba60354e6f30f540f68707c5751`

## 1. 목표

기능을 새로 늘리는 대신, 이미 구현된 세미나·참여·조 편성·회원·모집 관리 기능을 사용자가 업무 순서대로 찾고 안전하게 처리할 수 있도록 정리한다.

핵심 원칙은 다음과 같다.

1. 회원에게는 현재 해야 할 행동을 먼저 보여준다.
2. 운영자에게는 기능 목록보다 주간 업무 순서를 먼저 보여준다.
3. 기존 Flask 라우트, Supabase 테이블, 저장 형식은 변경하지 않는다.
4. 대형 레거시 화면은 전면 재작성하지 않고 점진적 보강으로 회귀 위험을 낮춘다.
5. 모바일에서는 가로 스크롤과 작은 조작 영역을 줄인다.
6. 저장·상태 변경에는 결과와 되돌리기 경로를 제공한다.

## 2. 이번 변경에 포함된 범위

### 2.1 공통 UI 계층

- 모든 현재 테마 적용 페이지에서 `static/app_ui.css`, `static/app_ui.js`를 로드한다.
- 기존 우드 테마 색상 토큰을 그대로 사용한다.
- 상단·하단 메뉴에서 현재 위치를 같은 규칙으로 표시한다.
- 공통 토스트가 없는 독립 페이지에서도 동작하는 피드백 폴백을 제공한다.
- 되돌릴 수 있는 상태 변경에 사용할 `wdToastUndo`를 제공한다.
- 헤더가 없는 레거시 페이지에는 최소 이동 도구를 추가한다.
- 기능별 enhancement를 오류 격리해 한 화면의 보조 기능 오류가 다른 기능의 실행을 막지 않게 한다.
- 새 서버 엔드포인트는 추가하지 않는다. 회원 상태 되돌리기만 기존 `/api/admin/members/<id>/set_status`를 재사용한다.

### 2.2 역할별 홈

- 비로그인: 동아리 설명과 로그인 진입점만 표시한다.
- 일반 회원·운영진: 현재 참여, 세미나, 내 활동으로 바로 이동한다.
- 관리자: 운영 개요, 세미나 운영, 조 편성 순서로 이동한다.
- 기존처럼 동아리명만 표시되는 빈 홈을 제거한다.

### 2.3 운영 개요

- 관리자 개요를 다음 5단계로 재구성한다.
  1. 도서·일정 확인
  2. 발제문 수집
  3. 참석자 확인
  4. 조 편성
  5. 기록 확인
- 기존 템플릿에 이미 전달되는 데이터만 사용해 활성 학기, 접수 중 발제문, 최근 기록을 표시한다.
- 회원, 모집, 행사, 벽돌책, 예약, 통계, 버그 제보를 업무 그룹별로 묶는다.

### 2.4 회원 세미나 목록

- 가장 가까운 예정 세미나를 강조한다.
- 예정 세미나와 지난 세미나를 분리한다.
- 지난 세미나는 기본적으로 접는다.
- 발제문 접수 중이면 직접 작성 링크를 표시한다.
- 월요일 추가 세미나 신청 링크를 카드와 상단에서 확인할 수 있게 한다.

### 2.5 참여 허브

- 첫 번째 열린 활동을 우선 작업으로 크게 표시한다.
- 나머지 열린 활동과 상시 책 추천을 분리한다.
- 열린 활동이 없을 때 다음 세미나와 내 활동으로 이동할 수 있게 한다.
- 관리자 전용 운영 링크는 관리자에게만 표시한다.

### 2.6 관리자 메뉴와 권한 노출

- 데스크톱 관리자 메뉴를 오늘, 주간 운영, 사람, 활동, 기록, 시스템으로 시각적으로 구분한다.
- 모바일에서는 긴 가로 스크롤 대신 현재 메뉴명을 보여주는 접이식 메뉴를 제공한다.
- 현재 백엔드에서 `officer`가 관리자 라우트에 접근할 수 없으므로, 운영진 계정에서 관리자 전용 링크를 숨긴다.
- 백엔드 권한을 넓히지는 않는다.

### 2.6.1 세미나 운영 주차 필터

- 학기 전체 주차 수, 예정 주차, 도서 확인 필요, 발제문 접수 중 건수를 화면 상단에 요약한다.
- 기본값은 예정 주차만 표시하고, 확인 필요·지난 세미나·전체 필터를 제공한다.
- 기존 `data-week` 카드와 문서 단위 이벤트 위임을 그대로 사용해 저장·불참·후기·조 편성 동작을 변경하지 않는다.

### 2.7 조 편성 입력

- 회차 확인 → 참석자·발제자 → 편성 설정 → 추천안 확인의 단계를 표시한다.
- 오해하기 쉬운 `투표자만`을 `신청자 명단 적용`으로 변경한다.
- 전체 선택·해제를 `일괄 선택` 메뉴로 묶는다.
- 발제자를 선택하면 참석자에도 자동 포함한다.
- 발제자 전체 선택과 붙여넣기에서도 같은 참석자 포함 규칙을 적용한다.
- 신청자 명단 적용 후 참석하지 않는 발제자는 자동 해제하고, 이전 선택으로 되돌릴 수 있게 한다.
- 참석자, 발제자, 예상 조 수와 조당 인원을 생성 전에 표시한다.
- 쉼표 문자열 입력 대신 조별 이름 입력칸을 생성하되, 기존 서버에는 동일한 쉼표 문자열로 전달한다.
- 조 편성 진행 화면의 문구를 한국어 업무 용어로 통일한다.

### 2.8 조 편성 결과

- 영문 제목을 한국어로 바꾼다.
- 여러 추천안을 탭으로 비교하며 한 번에 하나만 상세 표시한다.
- 실제 총점을 읽어 최고 점수 추천안을 표시한다.
- 키보드 방향키, Home, End로 추천안을 전환할 수 있게 한다.
- `이 조합으로 저장`, `결과 캡쳐`, `명단 수정`을 각각 `이 추천안으로 확정`, `공지 이미지 만들기`, `인원 이동·수정`으로 변경한다.
- 모바일에서 그룹 인원 이름이 한 줄 가로 스크롤에 갇히지 않도록 줄바꿈한다.

### 2.9 회원 관리

- 필터 결과의 현재 표시 인원을 보여준다.
- 모바일에서 1160px 표를 회원별 카드 형태로 재배치한다.
- 상태 변경 완료 후 되돌리기를 제공한다.
- 중복 회원 합치기 전에 삭제할 계정과 남길 계정의 주요 활동 수를 미리 보여준다.

### 2.10 모집 결과 관리

- 공개 설정, 명단 등록, 결과 입력, 발표 점검의 4단계 탭으로 나눈다.
- 결과 미입력 인원, 안내문, 링크 공개 상태, 발표 상태를 발표 전 점검 화면에서 확인한다.
- 기존 제출 폼과 API는 그대로 사용한다.

### 2.11 기타 화면

- 추가 세미나 신청의 `미정`을 `변경 없음`으로 명확히 하고, 사용자가 실제로 건드린 회차만 저장 전 요약에 표시한다.
- 마이페이지에서 통계보다 `지금 할 일`을 먼저 보여준다.
- 프로필 목록과 상세 화면의 영문 제목을 한국어로 바꾸고, 목록 검색과 글자 수 표시를 추가한다.
- 헤더가 없는 프로필 화면에 홈·회원 목록·내 활동 이동 경로를 추가한다.
- 기록 홈에 남아 있는 `장르` 관련 오래된 설명을 현재 기능에 맞게 보정한다.

## 3. 의도적으로 제외한 범위

### 3.1 Supabase 변경

다음 항목은 이번 작업에서 건드리지 않는다.

- SQL 마이그레이션
- 테이블·열·RLS 정책
- Storage bucket
- 기존 활동 기록 변환
- 회원 이름 기반 조 편성 기록을 회원 ID 기반으로 마이그레이션하는 작업

조 편성 데이터를 회원 ID 중심으로 바꾸는 것은 정확성 측면에서 권장되지만, 기존 저장 기록과 API 계약을 함께 변경해야 하므로 별도 데이터 마이그레이션 작업으로 분리한다.

### 3.2 Render·환경 설정 변경

다음 항목은 변경하지 않는다.

- `render.yaml`
- Dockerfile
- 환경변수
- 배포 플랜·헬스체크
- 자동 배포 설정

### 3.3 백엔드 권한 확대

현재 관리자 화면은 대부분 `role="admin"`으로 보호되어 있다. 운영진에게 링크만 보여주고 접근은 막히는 불일치는 수정하지만, `officer`에게 관리자 권한을 부여하는 변경은 하지 않는다. 실제 운영진 권한 범위는 개인정보·기록 수정 권한과 연관되므로 별도 정책 결정이 필요하다.

### 3.4 서버 데이터가 추가로 필요한 개인화

다음은 기존 템플릿 데이터만으로 정확히 구현할 수 없어 제외한다.

- 홈에서 개인별 제출 완료·미완료를 정확히 계산
- 관리자 개요에서 각 주간 단계의 실제 완료 여부를 모두 자동 판정
- 활동별 정확한 D-day와 마감 정렬

이번 구현은 기존 데이터로 가능한 우선순위와 이동 구조를 먼저 개선한다.

## 4. 검증 계획

### 자동 검증

- JavaScript 문법: `node --check static/app_ui.js`
- Jinja 문법: 변경 템플릿 5개를 `jinja2.Environment.parse`로 검사
- CSS 파싱: `tinycss2`로 오류 토큰 검사
- 새 UI 계약 테스트: `python -m unittest testing.test_ui_usability_overhaul -v`
- 실제 저장소 적용 후 전체 회귀 테스트: `python -m unittest discover -s testing -p "test_*.py" -v`
- 금지 범위 확인: 변경 파일에 `app.py`, `migrations/`, `render.yaml`, `Dockerfile`이 없는지 검사
- 서버 계약 확인: 새 API 경로가 추가되지 않았고 기존 회원 상태 변경 API만 호출하는지 검사

### 브라우저 검증

Chromium으로 다음 모의 화면을 데스크톱과 모바일에서 확인한다.

- 회원 홈
- 관리자 운영 개요
- 회원 세미나 목록
- 참여 허브
- 조 편성 입력
- 조 편성 결과 비교
- 모바일 회원 관리
- 모집 결과 관리 탭

확인 항목:

- 화면 가로 넘침
- 버튼·탭 터치 크기
- 숨김·펼침 상태
- 추천안 키보드 전환
- 관리자 모바일 메뉴 열기·닫기
- 필터 결과 수 갱신
- 조 이름 입력값의 원본 필드 동기화
- 모바일 회원 카드 재배치

## 7. 구현 안전장치

- 기존 폼의 `name`, `value`, 전송 방식은 유지한다.
- 조 이름 보조 입력은 기존 `group_names` 문자열로 다시 동기화한다.
- 추천안 탭은 기존 결과 카드와 저장·검증·캡처 이벤트를 그대로 사용한다.
- 회원 상태 되돌리기는 이미 존재하는 상태 변경 API만 호출한다.
- 운영진에게 관리자 링크를 숨기되 서버 권한은 변경하지 않는다.
- JavaScript가 비활성화되거나 enhancement가 실패해도 원래 서버 화면은 남는다.
- 정적 DOM 문자열 외의 사용자 데이터는 `textContent`로 삽입한다.
- 신규 회원가입 템플릿과 관련 라우트는 변경하지 않는다.

## 5. 적용과 되돌리기

이번 변경은 템플릿 5개와 공통 정적 자산 2개가 핵심이다. 문제가 생기면 `_app_theme_head.html`에서 `app_ui.css`와 `app_ui.js` 로드 2줄을 제거하면 대형 레거시 화면의 점진적 보강을 즉시 비활성화할 수 있다. 역할별 홈·운영 개요·세미나·참여 화면은 각 템플릿을 기준 커밋 버전으로 되돌리면 된다.
