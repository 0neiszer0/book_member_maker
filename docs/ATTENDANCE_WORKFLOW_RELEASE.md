# 출석·조 편성 운영 변경 — 2026-09-03

## 확정한 운영 기준

- 목요일: 카카오톡 **불참 투표자**를 기본 명단에서 제외합니다.
- 다음 월요일: 카카오톡 **참석 투표자**만 포함합니다. 정원과 선착순은 사용하지 않습니다.
- 목요일과 다음 월요일의 발제문 질문 목록은 공유합니다. 날짜와 사회자는 회차별로 저장합니다.
- 같은 목요일·다음 월요일에 모두 와도 학기 참석 기준에서는 **1회**입니다. 날짜별 출석표에는 각각 표시됩니다.
- 학기 기본 기준은 **3회**이며 운영진이 학기별로 변경합니다. 실제 세미나 출석, 인정 설정한 OT 출석, 벽돌책의 실제 모임 출석을 합산합니다.

## 매주 필요한 작업

1. **세미나 운영 → 해당 회차 → 명단 반영**에서 카카오톡 결과를 붙여넣거나 엑셀(.xlsx), 직접 선택으로 입력합니다.
2. 미리보기에서 반영 후 인원, 추가·제외 인원을 확인하고 저장합니다. 중복·동명이인·미등록 오류가 있으면 일부만 반영하지 않습니다. 명단 입력 결과는 직전 상태로 되돌릴 수 있습니다.
3. 조 편성에서 사람을 드래그하거나 이름을 선택해 이동합니다. ×로 뺀 사람은 미배정 목록에 남고, 완전히 제외하려면 사유를 적습니다. 미배정이 남으면 저장·캡처하지 않습니다.
4. Word 다운로드 전에 **회차와 사회자**를 확인합니다. 사회자가 비어 있으면 입력 화면으로 이동합니다.
5. 세미나 후 명단 반영 화면의 **실제 출석 확정**에서 실제로 온 사람만 확정합니다. 편성 저장이나 카카오톡 예정 명단은 실제 출석 확정이 아닙니다.
6. **학기 참석 현황**에서 미달 인원·날짜별 표·엑셀·공지 문구를 확인합니다. 개인 화면에는 본인 기록만 표시됩니다. 복사 버튼은 카카오톡 메시지를 자동 발송하지 않습니다.

## 발제문 마감

- 공유 링크는 마지막 연결 회차의 다음 날 **00:00, 한국시간**부터 제출·수정이 막힙니다. 통상 목요일+월요일 묶음은 화요일 00:00 마감입니다.
- 특정 회차를 지정한 제출 링크는 그 회차의 다음 날 00:00에 마감합니다. 이때 다른 회차의 공유 질문 목록 전체를 닫지는 않습니다.
- 서버에서 기한을 검사하므로 특정 페이지에 들어가야만 마감되는 구조가 아닙니다. ‘지금 참여하기’도 동일한 마감 기준으로 카드를 숨깁니다.
- 질문 열람과 기존 기록·Word 다운로드는 별개입니다.

## 기록과 개인정보 보호

- 조 편성에서 제외하는 것은 무단 불참 판정이 아닙니다. 실제 출석과 무단 불참 기록은 별도로 확인합니다.
- 만남 기록에는 확정된 실제 참석만 반영합니다. 현재·미래 편성과 무단 불참자는 이전 만남에서 제외합니다.
- 과거 조 편성을 수정해도 이미 확정된 실제 참석 명단은 유지됩니다. 독립 수동 기록은 명시적인 출석 확정 항목을 제공합니다.
- 명단 반영 내역과 미달 명단은 운영진 전용입니다. 새 이력 테이블과 명단 반영 함수는 서버 전용 권한을 유지합니다.

- 전체 Python 테스트 227개 통과: 날짜 경계, 실제 출석 합산, 중복·동명이인, 권한·CSRF, Word 날짜·사회자·문서 XML, 기존 기능 회귀 포함.

- 로컬 PostgreSQL(PGlite)에서 새 마이그레이션 실행, 재실행, 명단 반영 트랜잭션, 충돌 감지, 이력 저장, RLS와 실행 권한 검사 통과.
- CSS 빌드, JavaScript 문법 및 변경 파일 형식 검사 통과.

## 운영 반영 시 필요한 순서

2026-09-03 운영 반영 승인을 받아 DB 마이그레이션을 적용했습니다. 기존 회원 117명·세미나 기록 58건·발제문 86건이 유지됐고, 월요일 정원 해제 및 새 이력·함수의 서버 전용 접근 권한을 확인했습니다. 아래 순서로 코드 push와 배포 후 점검을 진행합니다.

1. 현재 배포 버전·DB 백업을 확인하고, 운영 반영 시점을 정합니다.
2. `supabase/migrations/20260903103757_seminar_attendance_and_moderators.sql` 적용 완료. 로컬 파일명은 Supabase가 기록한 실제 버전과 맞췄습니다. 새 필드와 서버 전용 명단 반영 이력을 추가하고 월요일 정원을 해제했으며, 회원·발제문·조 편성 기록은 삭제하지 않았습니다.
3. 기존 과거 기록은 기존 출석 의미를 보존하도록 확인 시각을 한 번만 보충합니다. 오늘·미래 기록과 새 편성은 자동 확정하지 않습니다. 기존 무단 불참 기록은 집계에서 제외합니다.
4. 검증한 코드를 main에 올리고 Render의 해당 버전 배포 완료를 확인합니다. 새 코드는 추가 필드가 필요하므로 **DB 변경이 먼저**입니다.
5. 운영진 권한으로 회차 명단 미리보기, 기존 기록 열기, 실제 출석 현황, 사회자 설정·Word 다운로드를 점검합니다. 일반 회원 계정에서는 본인 현황만 볼 수 있는지 확인합니다.
6. 첫 운영 주에는 기존 출석 표본과 새 학기 합계를 비교하고, 아직 확정하지 않은 회차 목록을 확인합니다.

문제가 생기면 새 데이터를 삭제하거나 새 필드를 제거하지 말고 먼저 코드 버전과 오류를 확인합니다. 새 출석·반영 이력이 생긴 뒤의 롤백은 해당 이력을 보존하는 방향으로 별도 판단해야 합니다.
