# 회원 식별자 정리 기록

점검일: 2026-09-01

## 운영 데이터 점검 결과

- 중복 학번: 1그룹, 회원 2명
- 내부 회원 ID: `1000`, `1027`
- 이름: 서로 다름
- 학과: 서로 다름
- 성별과 기수: 같음
- 로그인 연결 및 이메일: 두 계정 모두 없음
- ID 기반 외래키 활동: 두 계정 모두 0건
- 이름 기반 과거 세미나 참석: 각 1건
- 이름 기반 조 편성 만남 행: 각각 4건, 3건
- 발제문 이름 연결: 두 계정 모두 0건

두 계정은 서로 다른 이름과 학과로 실제 과거 활동이 있으므로 자동 병합하지 않는다.
중복 계정이라기보다 한쪽 학번 오입력 가능성이 높다.

## 관리자 처리 방법

1. `운영 관리 > 기록·통계 > 회원`으로 이동한다.
2. 상단의 `중복 학번만 보기`를 누른다.
3. 주황색 행의 이름·학과·내부 ID를 원본 회원 명단과 대조한다.
4. 잘못 입력된 회원의 `편집`을 눌러 올바른 학번으로 수정한다.
5. 같은 학번이라는 이유만으로 `중복 회원 합치기`를 사용하지 않는다.

앱은 새 회원 추가 또는 기존 학번 변경 시 이미 사용 중인 학번을 409 응답으로
차단한다. 현재 중복 계정의 학번을 바꾸지 않고 다른 정보만 편집하는 것은 허용해
운영진이 단계적으로 정리할 수 있게 한다.

## 후속 DB 제약

운영진 수정 후 중복 학번 집계가 0인지 확인한다. 그다음 별도 additive migration으로
trim된 비어 있지 않은 학번에 partial unique index를 추가한다. 기존 중복이 남은 동안
인덱스를 먼저 적용하거나 두 계정을 자동 병합하지 않는다.
