# 동아리방 예약 — 배포 전 확인

## 사용 흐름

- 홈의 오늘 빈 시간 카드 또는 `동아리방` 메뉴 → 날짜/시간 선택 → 대표자·참여자 입력.
- 로그인 없이 1시간 단위로 신청한다. 자정 넘김과 여러 날 예약을 허용한다.
- 일반 예약끼리는 한 번 확인한 뒤 겹쳐 신청할 수 있다. 공개 시간표에는 대표자만 표시한다.
- 신청용 공용 코드는 없다. 수정·취소용 개인 관리 코드는 자동 발급·브라우저 저장하며 다른 기기에서는 붙여넣는다. 공용 기기에서는 저장된 코드를 지운다.
- 로그인한 활성 임원/관리자만 회의를 등록하고 전체 참여자·목적을 확인한다.
- 회의는 이후 일반 예약의 신규 신청/시간 이동을 막는다. 이미 있던 예약은 **자동 취소하지 않는다**. 관리 목록에서 겹친 대표자를 보고 직접 조율한다.
- 회의 취소 후 일반 예약을 다시 받는다. 동아리방 예약은 학기 출석에 포함하지 않는다.

## 운영 반영 순서

2026-10-05 운영 DB에 예약 구조를 추가했다. 파일명은 Supabase의 실제 적용 이력 `20261005122140`에 맞췄다. 기존 기준선 이력은 건드리지 않았다.

1. 대상 Supabase 프로젝트 및 기존 migration 이력 확인. 전체 미적용 migration을 무심코 일괄 적용하지 않는다.
2. `supabase/migrations/20261005122140_club_room_bookings.sql` 적용 여부 확인. 기존 회원/세미나 데이터는 변경하지 않으며 예약 테이블 2개와 쓰기 함수만 추가한다. 이미 적용된 운영 프로젝트에는 재실행하지 않는다.
3. Flask 코드 배포. 기존 `SUPABASE_SERVICE_KEY`, `FLASK_SECRET_KEY`를 사용하며 새 환경변수나 운영 패키지는 없다. `FLASK_SECRET_KEY` 변경 시 기존 개인 관리 코드 검증도 바뀌므로 임의 교체하지 않는다.
4. 익명 시간표 조회, 로그인한 임원 화면, 일반 회원에게 회의 버튼이 없는지 확인한다. 실제 예약을 만들거나 취소하는 운영 테스트는 별도 동의 후 한다.
5. 배포 중단 시 이전 앱 버전으로 되돌리고 예약 테이블은 보존한다. 스키마를 삭제하는 롤백은 하지 않는다.

## 안전장치

- 공개 응답은 필드 허용목록을 사용한다. 회의는 이름/명단/식별자 없이 `이용 불가` 시간만 공개한다.
- 예약·감사 테이블은 RLS 활성화, anon/authenticated 직접 접근 금지. 쓰기 함수는 SECURITY INVOKER + service_role 전용이다.
- 서버와 DB가 현재 임원 권한을 재확인한다. 회의는 개인 관리 코드만으로 관리할 수 없다.
- CSRF, 입력 검증, 개인 코드 HMAC, 익명 IP별 10분 20건 신청 제한을 적용한다.
- 한 공간의 쓰기는 트랜잭션 잠금으로 직렬화한다. 버전 충돌은 덮어쓰지 않는다. 같은 신청 재전송은 중복 생성하지 않는다.
- 취소는 원본·변경 이력을 보존한다. 감사 이력에 코드 해시와 IP 식별값은 넣지 않는다.
- 조회 실패를 빈 시간으로 표시하지 않으며, 저장 실패 시 입력을 유지한다.

## 재검증

2026-10-05 로컬 결과: Python 295개 전부 통과, 기존/신규 JavaScript 검사 8종 통과, PGlite SQL 검증 통과. 아래 브라우저 점검도 합성 데이터로 완료했다. 운영 DB 적용 후 테이블 RLS와 서버 전용 조회·실행 권한을 확인했다. 운영 검증에서는 실제 예약을 임의 생성·취소하지 않는다.

```text
python -m unittest discover -s testing -p 'test_*.py'
node testing/test_club_room.js
node --check static/club_room.js
```

실제 SQL 검증은 별도 임시 폴더에 설치한 `@electric-sql/pglite@0.5.8`로 수행한다. 운영 의존성에 추가하지 않는다.

```text
node testing/test_club_room_database.mjs <PGlite의 dist/index.js 절대 경로>
```

PGlite 검증은 일회용 PostgreSQL에서 실제 migration/RPC를 실행한다. 실제 Supabase 연결 또는 여러 DB 연결의 동시 부하 테스트를 대체하지 않는다.

브라우저 점검: PC 1280px, 모바일 390/320px에서 겹침 신청, 날짜 넘김 수정, 취소, 회의와 기존 예약 공존, 새 일반 예약 차단, 개인정보 비노출, 장애 시 빈 시간 오표시 방지를 확인한다. 이때는 운영과 분리된 합성 데이터만 사용한다.
