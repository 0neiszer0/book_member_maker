## 승인받아 완료한 배포 범위

1. Ubuntu에 고정 버전 엔진 `/opt/bookmembers-wiki/opennamu` 설치. 외부로 노출하지 않고 `127.0.0.1:5096`에서만 실행. 자동 업데이트 끔. 재시작/부팅 자동 실행, 메모리 제한, 네트워크는 loopback으로 제한.
2. `/var/lib/bookmembers-wiki/data.db`에 14개 초안과 19개 이력을 보존해 이전. 기존 로컬 예시 계정 암호는 무효화하고 운영 연동 키를 서버에서 새로 생성한다. 본문·이력은 그대로다. 로컬 예시 작성자명은 과거 이력으로 남고 실제 회원에게 재배정하지 않는다.
3. `/etc/bookmembers-wiki/{bridge,engine}.env` root 전용 파일과 앱 systemd drop-in으로 활성화. 기존 app.env 비밀값은 변경하지 않는다. 위키 메뉴는 기존 Notion 연결을 회원 위키로 대체한다.
4. 위키 CSS 포함 CDN·앱 배포 후 앱만 재시작. Supabase SQL·Render·GitHub main·도메인·카카오 설정은 변경하지 않는다.
5. 일관된 SQLite·키·첨부 파일의 로컬 백업을 하루 1회, 최근 7회 보관. 같은 VM 안의 백업이므로 PC 고장에는 대비하지 못한다. 외부 암호화 백업은 기존 미완료 운영 과제로 남는다.

위키 엔진의 관리실·가입·파일 업로드·문서 이동/삭제 API는 공개 앱에 연결하지 않는다. 지원 범위는 읽기·검색·편집·새 문서·미리보기·수정 이력이다. 본문은 운영 규정을 임의 확정하지 않은 초안이며 회원이 편집할 수 있다.

## 복구 및 재개

- 준비물과 상태: 작업공간 `work/wiki-release/`, `outputs/wiki-integration-state.json`.
- 앱 회귀 시 이전 앱/정적 manifest로 돌아가고 wiki drop-in과 두 타이머/서비스의 새 설치를 비활성화한다. SQLite·키·백업은 삭제하지 않는다. 필요한 경우 Worker 직전 버전으로 복구한다.
- 위키 DB 복원은 앱과 엔진을 중단한 뒤 SQLite, 첨부, 두 환경 파일을 같은 스냅샷에서 복원한다. DB/첨부는 bookapp, 키는 root:root 0600. WAL/SHM은 활성 DB와 섞지 않는다. 재기동 후 무결성·문서 수·읽기/저장을 확인한다.
- DB와 연동 키는 함께 보관한다. 검색 인덱스는 원본 데이터가 아니며 재생성 가능하다. PC별 절대 경로를 코드에 넣지 않고 환경 설정과 서비스 경로를 사용한다.
