# 로그인 유지 · 학기별 회원 관리

## 사용 순서

운영 관리 → **학기별 회원**에서 학기를 선택합니다. 새 학기는 연도·1학기/여름학기/2학기/겨울학기·첫 세미나 날짜·마지막 세미나 날짜로 만들 수 있습니다. 도서·사회자 일정은 별도 연결 버튼으로 이동합니다.

1. 새 학기를 만들면 직전 운영 묶음의 활동 회원이 자동으로 들어옵니다. 1학기·여름학기와 2학기·겨울학기는 각각 한 묶음이며, 두 학기가 있는 묶음은 활동자를 합쳐 중복 없이 승계합니다.
2. 계속 활동할 회원은 활동, 이번 학기에 쉬는 회원은 휴식, 종료한 회원은 종료로 지정합니다. 검색 결과 일괄 변경도 가능합니다.
3. 화면에는 해당 학기 명단만 먼저 표시됩니다. 빠진 기존 회원은 ‘직전 활동자 중 미포함’ 또는 ‘다른 회원 찾기’에서 추가하고, 처음 온 회원은 신규 등록합니다. 신규 등록은 전체 회원에 즉시 저장되지만 학기 명단은 명단 저장을 눌러야 반영됩니다.
4. 활동 인원과 전체 명단 인원을 확인하고 저장합니다. 동시 편집 충돌은 덮어쓰지 않고 새로고침을 안내합니다.

학기 명단은 글로벌 계정 상태·로그인 권한과 별개입니다. 목요일 기본 참석 대상, 월요일 카카오 명단 입력 대상, 조 편성 후보, 학기 참석 기준 대상이 해당 학기를 따릅니다. 이미 반영한 참석 예정 명단·실제 참석·과거 조 편성은 자동으로 변경하지 않습니다.

과거 학기 명단은 당시 자료를 확인하고 저장해야 합니다. 새 학기는 직전 확정 명단의 활동 회원을 자동 승계하며, 이어받을 확정 명단이 없을 때만 빈 명단으로 시작합니다. 도입 시점의 2026-2학기는 당시 전역 활성 회원을 시작 명단으로 한 번 반영했습니다.

## 로그인

- 기본적으로 같은 브라우저에서 마지막 접속 후 90일간 로그인 상태 유지. 접속 시 만료일 갱신.
- 로그인 화면에서 체크를 해제하면 브라우저 세션 쿠키 사용. 브라우저의 세션 복원 기능 때문에 공용 기기에서는 반드시 로그아웃할 것.
- 기존 로그인도 보호된 페이지에 접속하면 유지 설정을 적용. HttpOnly, SameSite=Lax, 운영 HTTPS Secure 쿠키 사용.
- 모든 보호된 페이지에서 계정 승인·비활성 여부와 최신 권한을 재확인. 확인 실패 시 접근 차단. 카카오 닉네임은 등록 실명을 덮어쓰지 않음.
- 카카오톡 내장 브라우저와 Chrome/Safari, 시크릿 창, 다른 기기는 쿠키를 별도로 보관할 수 있음. 쿠키 삭제·기기 정책·서버 비밀 키 변경 시 재로그인 필요.

## 데이터 보호와 검증

`seminar_term_members`는 학기/회원 복합 키이며 상태·참여 구분을 저장합니다. `seminar_term_roster_changes`에 변경 전후와 작성자를 같은 트랜잭션으로 저장합니다. 새 테이블과 함수는 서버 service_role만 접근하며 RLS를 적용합니다. 학기 명단 저장과 카카오 명단 반영 사이의 동시 변경도 학기 revision을 잠그고 검증합니다.

기존 회원 합치기는 일부 기록만 이전하는 방식이라, 학기 명단이 있는 원본 회원의 삭제를 사전 차단합니다. 해당 회원의 합치기는 안전한 통합 이전 기능이 준비되기 전까지 지원하지 않습니다. 이 제한은 기록 유실 방지를 위한 것입니다.

검증: 로그인 쿠키 재사용·로그아웃·권한 회수, 학기 분리·빈 명단·기존 명단 호환·잘못된 데이터·권한·CSRF·동시 편집, 실제 PostgreSQL 문법으로 저장/롤백/RLS 확인. UI는 가상 명단으로 이전 회원 불러오기, 휴식 변경, 복귀 및 신규 추가, 저장/재조회, 겨울학기 생성과 320/390px 모바일 화면을 확인합니다. 실제 카카오 계정의 인증 과정이나 물리 기기의 브라우저 재시작을 대신 수행하지는 않습니다.
