# 실제 암호화 백업·격리 복원 결과

2026-10-29. 사용자가 age 설치, root 전용 백업 설정, 개인 Google Drive 업로드, 두 번의 격리 복원을 승인했다. 불필요한 반복 검증을 줄이라는 요청에 따라 전체 앱 테스트는 다시 돌리지 않았다. **운영 DB 연결은 아직 Supabase다.**

## 완료

- Ubuntu age 1.1.1 설치(추가 패키지1개, 기존 서비스 재시작 없음). Windows portable age 1.3.2는 공식 ZIP SHA256과 대조했다.
- 복구 개인키는 Windows DPAPI로 보관하고 사용자가 별도 1Password 항목 저장을 확인했다. VM에는 공개키만 저장했다. 복원 작업의 복호화는 Windows에서 실행했으며 개인키를 VM에 보내지 않았다. 1Password에서 다시 꺼내 쓰는 독립 복구까지 실증한 것은 아니다.
- root 전용 DB 비밀번호/설정과 공식 CA 설치. 실제 DB public·supabase_migrations, Storage 설정/객체, 위키 SQLite snapshot, 앱/위키 설정을 age로 암호화했다.
- 암호문 약932KB를 개인 Drive의 소유자 단독 접근 폴더에 업로드했고, 실제 재다운로드한 파일의 SHA256이 일치했다. 원본·외부 사본으로 새 볼륨 두 곳에 각각 복원했다.
- PostgreSQL 15.8 → 고정 PG17.6.1.136 복원 성공. 원본 확장 6개가 대상 이미지에 모두 있다. public 스키마 초기 상태만 정리한 새 DB에 덤프를 단일 트랜잭션으로 적용했고 앱 migration을 중복 실행하지 않았다.
- 테이블72개 전부의 행 수, RLS72개, 제약조건320개, 테이블/함수 권한·소유자, 시퀀스가 원본 읽기 전용 기준값과 일치했다. 익명 private inbox 접근 거절, service_role API 조회 성공.
- Storage 버킷4개와 공개/비공개 속성 복원. 원본 파일은0개이므로 실제 회원 파일 내용 복원 항목은0개다. 파일 업로드/서명 URL 기능은 직전 합성 시험에서 검증했다.
- 위키 SQLite integrity_check 성공, 문서14개/이력32개 확인. 설정 파일을 포함한 복구 파일4개의 해시 검증 성공.
- 마지막 복원+필수 검사 약12.8초(컨테이너 초기화/다운로드 시간 제외). 마지막 관측 컨테이너 메모리 합계 약184MiB. 부하 시험이나 피크 메모리 보장은 아니다.
- 종료 후 합성/복구 컨테이너 모두 중지, 전용 볼륨 보존. 원본 비밀 설정을 포함했던 임시 평문 TAR와 위키 파일은 정리했다. VM 여유 RAM 약2GiB, 디스크18GB. 운영 앱·위키·Tunnel active, 공개 로그인 GET200.

## 해결한 차이와 한계

- 최초 임시 배치 경로가 원본 디렉터리 구조와 달라 백업의 출력 경로 검사가 중단됐다. `infra/minipc` 구조대로 배치해 해결했다. 이후 백업은 성공했으며 원본 쓰기나 코드 수정은 없었다.
- Docker internal 네트워크에서는 호스트 포트가 실제 게시되지 않았다. 외부 통신 차단을 유지하고 호스트에서 검증된 Docker 내부 주소로만 검사했다. 복구 API는 인터넷/호스트 포트에 공개되지 않았다.
- PG17은 소유자에게 새 MAINTAIN 권한을 표시한다. 처음 ACL 문자열 비교에서 이 차이만 발견됐다. **소유자의 MAINTAIN 항목만 정규화**하고 비교하니 모든 권한이 일치했다. 다른 사용자나 service_role 권한 차이는 무시하지 않았다. [PostgreSQL17 공식 변경 기록](https://www.postgresql.org/docs/17/release-17.html#RELEASE-17-PRIVILEGES).
- 첫 복원 후 파일 API 주소 진단을 위해 이어서 검사했으므로 첫 결과의 시간은 전체 복원 시간이 아니다. 두 번째는 처음부터 마지막 검사까지 약12.8초다.
- 백업 중 사이트 쓰기를 멈추지 않았다. 현재 읽기 전용 기준값과 일치했지만 최종 전환용의 서비스 전체 동시 시점 백업을 대신하지 않는다.
- 실제 알림·메일·Telegram·공개 트래픽은 복구 환경에서 시작하지 않았다. 운영 앱 환경변수/소스, Worker, Render, GitHub main, 도메인, 카카오 설정은 바꾸지 않았다.

## 남은 작업

1. 서버가 스스로 실행하는 외부 자동 백업: 사용자 소유 Google OAuth client, drive.file 전용 폴더, 토큰 수명, 보존 정책/실패 알림을 준비하고 설치 승인받기. 이번 Drive 연결 도구는 수동 사본이며 상시 서버 자동 백업이 아니다.
2. 운영용 로컬 DB 서비스 구성·의존 순서·메모리 여유, 앱 이미지 주소 전환 설정을 구체화. 실제 전환 직전 앱/위키/타이머 쓰기 중지와 최종 백업·복원·연결 변경·서비스 재시작 승인받기.
3. 사용자 승인 후 Windows 전체 재부팅으로 VM→DB/API→앱/위키/알림→Tunnel→사이트 자동 복구 실증.

상세 비밀 경로·Drive 파일 ID·테이블별 비교 결과는 이 PC의 작업 폴더 `outputs/operations-improvements-state.json`, `outputs/localdb-restore-a-results-20261029.json`, `outputs/localdb-restore-b-results-20261029.json`에 저장한다. 저장소에 키/회원 내용/개인 Drive 계정 정보를 추가하지 않는다.
