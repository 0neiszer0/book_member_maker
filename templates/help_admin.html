학기가 바뀔 때: 회원 명단부터

학기별 회원 관리 열기 → 새 학기 생성 → 자동으로 들어온 직전 활동자 확인 → 쉬거나 그만둔 사람만 상태 변경 → 신규·복귀 회원 추가 → 저장 순서입니다.

1학기와 여름학기, 2학기와 겨울학기는 각각 한 묶음으로 봅니다. 2학기를 만들면 같은 해 1학기·여름학기 활동자가 합쳐져 자동으로 들어오고, 다음 1학기는 직전 2학기·겨울학기 활동자를 이어받습니다. 명단 구분(계속 활동·신규·복귀)은 직접 수정할 수 있습니다.

화면에는 해당 학기 명단만 먼저 보입니다. 빠진 기존 회원이 있을 때만 ‘직전 활동자 중 미포함’이나 ‘다른 회원 찾기’를 누르세요. 학기 명단 변경은 이미 반영한 카카오톡 투표·확정 출석을 덮어쓰지 않습니다.

카카오 로그인은 같은 브라우저에서 마지막 접속 후 90일간 유지됩니다. 공용 기기는 로그인 화면에서 유지 체크를 해제하고 사용 후 로그아웃하세요. 카카오톡 안의 브라우저와 Chrome·Safari는 로그인 상태를 따로 보관할 수 있습니다.

매주 하는 일세미나 당일회원 관리학기 시작학기 종료연 1회·인수인계기록 수정문제 발생 시

매주 하는 일

1
도서·저자·안내 저장

세미나 운영 → 학기·도서 일정 도구에서 날짜를 고르고 도서·저자·안내와 목·월 사회자를 함께 입력합니다. 도서는 두 회차·발제문·연결된 기록에 공유되고, 사회자는 회차별로 저장됩니다. 날짜를 바꿔도 작성 중인 내용은 유지되며, 변경한 일정 모두 저장도 가능합니다.

2
발제문 수집 열기

링크를 카톡방에 공유하고 제출 인원을 확인합니다. 목요일·월요일은 발제문을 공유하며 마지막 회차 다음 날 00시(한국시간)에 제출·수정이 마감됩니다. Word 다운로드 전 회차별 사회자를 확인합니다.

3
카카오톡 투표 명단 반영

목요일은 불참 투표자, 월요일은 참석 투표자를 입력합니다. 붙여넣기·엑셀·직접 선택 후 미리보기에서 이름과 추가·제외 인원을 확인하고 반영합니다. 정원·선착순 제한은 없습니다.

4
조 편성 후 저장

전체 인원, 미배정 인원, 발제자와 만나면 안 되는 조합을 확인하고 결과를 저장합니다.

5
실제 출석 확정

세미나 후 명단 반영 화면에서 실제 참석자를 선택해 확정합니다. 조 편성 저장만으로는 학기 참석 횟수가 올라가지 않습니다. 미연락 불참 기록도 확인합니다.

세미나 당일·직후

  • 실제 참석자와 조 편성 결과가 맞는지 확인
  • 연락 없이 빠진 사람은 해당 회차의 무단 불참으로 등록
  • 결과 화면 캡처 후 공지하고, 저장된 진행 기록 열기
  • 후기를 받을 때만 후기 링크를 만들고 공유
무단 불참자는 그 회차에서 “서로 만난 날짜·횟수” 계산에서도 자동 제외됩니다. 잘못 등록했다면 취소하면 만남 기록도 다시 계산됩니다.

회원 관리

회원 관리의 각 회원 행에서 활성·휴면·비활성 버튼을 누르면 즉시 저장됩니다.

활성

기본 계정 상태. 학기를 확정하면 참석 대상은 학기 명단으로 관리

휴면

기록은 유지, 기본 명단 제외

비활성

졸업·탈퇴 등 장기 미활동

관리자 지정과 “만나면 안 되는 조합”은 권한이 있는 소수 관리자만 다룹니다. 관리자 변경은 다음 권한 확인 요청부터 반영됩니다. 학기 명단의 휴식·종료는 로그인 권한을 바꾸지 않습니다.

학기 시작에 한 번

  • 새 학기를 만들고 첫·마지막 세미나 날짜, 자동 생성된 목·월 날짜 확인
  • 학기별 회원에서 자동 승계된 직전 활동자를 확인하고, 쉬는 사람만 휴식·종료로 변경한 뒤 명단 저장
  • 신입 회원의 이름·학번·학과·기수 입력 및 중복 계정 확인
  • 생성된 날짜를 선택해 도서·사회자 입력 후 저장 (여러 일정 붙여넣기도 가능)
  • 세미나실 예약 현황 확인
  • 학기 참석 현황에서 기본 3회 기준을 확인하고 공지 문구 복사
  • OT 실제 참석 명단을 행사 관리에 등록한 후 학기 참석 현황에서 OT 인정 설정
  • 운영진이 직접 로그인해 세미나 운영·회원 관리 권한 확인

같은 주 목요일과 다음 월요일은 모두 참석해도 학기 기준에서 1회입니다. 벽돌책 가입이 아니라 실제 모임 참석 기록만 합산합니다.

붙여넣기 예시 · 2026-09-03 | 도서 제목 | 저자명 | 1~4장 읽기
입력 내용 확인·채우기로 날짜를 검증한 뒤 저장합니다. 빈 칸은 기존 값을 유지합니다.

학기 종료에 한 번

  • 세미나 진행 현황에서 도서명·발제자·조 편성 누락 확인
  • 출석 매트릭스를 학기로 필터링하고 엑셀 내려받기
  • 발제·벽돌책·소모임·행사 기록이 회원 프로필에 반영됐는지 표본 확인
  • 현재 학기를 삭제하지 말고 보관
  • 다음 학기를 만들면 직전 활동자가 자동으로 들어옵니다. 쉬는 회원만 새 학기에서 휴식으로 바꾸고 지난 학기는 그대로 보관

연 1회 또는 운영진 인수인계 때

  • 실제 관리자 1~2명과 운영진 권한이 맞는지 확인
  • Supabase·Render·GitHub 소유자와 결제·복구 연락처 확인
  • 카카오 로그인 설정의 운영 URL과 담당자 확인
  • 최근 학기 출석 엑셀과 필요한 운영 문서를 운영진 전용 공간에 보관
  • 새 담당자가 테스트 회원으로 로그인해 주간 운영 한 번 실습
비밀번호·API 키·서비스 비밀값은 공개 위키나 단체 채팅에 적지 마세요. 공식 안내는 Notion 공개 위키, 민감한 인수인계는 운영진 전용 저장소를 사용합니다.

과거 기록을 수정할 때

  1. 세미나 진행 현황에서 날짜·도서 편집 또는 상세를 선택합니다.
  2. 상세 화면에서는 이름을 잡고 끌어 옮깁니다. 모바일은 길게 누르면 이름 카드가 손가락을 따라옵니다. 이름을 한 번 눌러 이동할 조를 고를 수도 있습니다. 이어서 발제자를 지정하고, 공지 이미지를 다시 만들 수 있습니다. 빼놓은 사람은 미배정 목록에서 확인하고, 완전히 제외하려면 사유를 남깁니다.
  3. 일정에 연결된 기록의 도서명은 같은 주의 목·월 일정과 발제문에도 동기화됩니다.
  4. 만남 기록과 학기 참석 횟수에는 확정된 실제 참석만 반영됩니다. 조 편성에서 사람을 빼는 것과 무단 불참 처리는 별개입니다.

그날 저장하지 못한 회차만 “과거 세미나 수동 추가”를 사용하세요. 이미 있는 회차를 다시 만들면 중복 기록이 생깁니다.

문제가 생겼을 때

  1. 새 회차를 만들거나 기존 기록을 삭제하지 말고, 먼저 새로고침 후 같은 문제가 반복되는지 확인합니다.
  2. 화면 아래 버그 제보에 날짜, 화면 이름, 누른 버튼, 기대한 결과를 적습니다.
  3. 버그 제보 관리에서 접수 내용을 확인합니다.
  4. 배포 후에는 세미나 운영 화면과 공개 발제문 링크를 각각 확인합니다.
